# 扣款后余额与“生活”分类规划

日期：2026-11-08。状态：方案已整理，尚未实施。

本次仅规划两个需求：每笔支出显示该笔扣款后的余额；新增“生活”支出分类。以下口径为建议默认值，尚不代表用户已逐项确认。不修改应用代码、用户账本或线上版本。

## 1. 展示范围与文案

覆盖首页最近账单、账单页每笔支出、统计页选中日期的每笔消费，以及点击支出后打开的明细/编辑弹窗。每笔原有金额、分类和备注继续保留。

建议在支出金额下方增加次级文字：`扣款后余额 ¥1,480.00`。手机窄屏可将该文字放在该笔记录的独立下一行，避免长备注挤压金额。负余额显示 `扣款后余额 −¥5.00`，同时增加“已超支”文字；零余额正常显示 `¥0.00`。兼容浅色与深色主题。

此处余额定义为“该笔支出发生后，该月份的预算余额”，与首页本月余额采用同一计算规则。历史结余仅在主动划转后进入预算。不是今日剩余额度，也不是银行卡余额。查看旧月份时，显示那个月当时的预算余额。

本期展示限定普通支出；收入、退款和内部划转仍必须参与余额计算，暂不增加它们的余额展示要求。

## 2. 逐笔余额计算

扩展现有账本重放逻辑，在每笔收支或划转处理后记录预算余额，形成以 entry.id 为键的内存映射，供各页面共同查询。不在账单中永久保存 balanceAfter，避免补记、修改和删除后出现过期数值。

计算顺序为发生日期升序、createdAt 升序、id 升序。同一天暂用录入顺序表达先后，不新增消费时间字段；编辑保留原 createdAt。列表可以继续倒序展示，但同日平局规则与计算保持一致；统计明细也使用确定的排序。

必须先使用完整账本计算，再应用月份、分类、搜索和首页最近五笔等展示筛选。禁止仅用筛选结果累计，也不能把某一天的日终余额显示成当天每笔的余额。

复用当前规则：

- 支出扣减预算，收入和退款增加预算，划转同步改变预算与历史结余。
- 正余额跨月进入历史结余，负余额作为缺口进入下月。
- 起始资金按现有基准月份规则注入，不因旧记录提前注入历史月份。
- 首次设置产生的“已含起始余额”生活费收入不重复增加预算。
- 旧 includedInOpening 字段继续不影响预算，不恢复已移除的历史排除逻辑。
- 金额保持整数分计算，统一格式化为两位小数，允许出现负余额。

补记、编辑、删除、撤销、恢复备份及其他标签页更新后，后续受影响的逐笔余额随当前账本重新计算。因此它是“按当前账目还原的该笔后余额”，并非首次保存时不可变的历史快照。更早记录变动可能通过跨月结转影响后续月份。

现有数据只有消费日期和录入时间，无法还原同一天未记录的实际消费时刻；本期不扩展时间输入。余额基准日前的记录沿用现有账本推导口径，不推测未录入资金或真实银行资产。

性能上一次排序和一次重放生成映射，按账本数据变更复用计算结果，不为每一行从头重放全部记录。

## 3. “生活”支出分类

新增名称为“生活”、类型为“支出”的默认分类，建议顺序为餐饮、交通、购物、生活、娱乐、学习、其他。定位于日用品、水电、洗护等日常生活消费，与收入分类“生活费”区分；用户自行选择，不自动重分历史购物或其他账单。

接入新增/编辑支出、账单筛选、分类排行、分类管理和现有备份导出。增加适合生活用品的图标，沿用现有视觉风格。

兼容方案：

1. 新账本直接包含“生活”，使用独立稳定 ID；保持所有现有分类 ID 不变，不能因插入默认名称而让旧 expense-3 等 ID 指向不同分类。
2. 旧账本升级时在事务内补齐缺失分类，幂等执行；事务以最新账本为准，遵守 revision 和跨标签页通知规则。
3. 已有同类型同名“生活”则复用其 ID；已有项被停用时保留停用状态，不自动启用、不另建同名项。“生活费”或同名收入分类不替代支出分类。
4. 恢复旧 JSON 备份时同样补齐；原账单、分类引用和金额均保留。恢复前副本保持现有保护流程，补齐结果通过正常校验。
5. 分类已达到现有限额或稳定 ID 冲突时需要显式处理，不能让更新导致整个账本无法打开或覆盖现有分类。

本期不扩展多级分类、自动识别、批量重分类或新的分类排序管理功能。

## 5. 验收场景

| 场景 | 预期 |
| --- | --- |
| 同月预算 1500，先支出 20，再支出 15 | 两笔分别显示 1480.00、1465.00，倒序展示仍对应各自余额 |
| 中间插入收入或退款 100，再支出 5 | 后一笔包含该笔入账，按 1465 + 100 − 5 显示 1560.00 |
| 同日多笔收入、支出和退款 | 各笔按稳定顺序计算，不能全部显示当天最终余额 |
| 筛选生活分类、搜索备注、首页只展示五笔 | 同一笔在所有入口显示相同余额，不遗漏被筛掉的交易影响 |
| 预算 10，支出 15 | 显示负余额 −5.00 和超支状态，未截断成零 |
| 上月末为 −50，下月收入 1500 后支出 20 | 该支出后余额为 1430.00 |
| 上月正结余 100，下月收入 1500 后支出 20 | 该支出后预算余额为 1480.00；历史结余仍独立 |
| 存在初始生活费标记或基准日前补记 | 与现有首页预算结果一致，不重复入账、不改变旧规则 |
| 补记、编辑金额/日期、删除和撤销历史记录 | 受影响记录及时重算，编辑不重置同日顺序 |
| 新账本、旧账本升级、旧备份恢复 | “生活”可选，历史分类 ID 及原账单引用不变 |
| 用户已手动建立或停用“生活”；重复刷新或并发打开 | 不重复添加，不强制启用，不丢失其他标签页已保存内容 |
| 手机 320px、常见手机宽度、桌面和深色主题 | 金额与余额可读，长备注不造成横向溢出 |

实现完成后再运行相关单元测试、浏览器场景及生产构建。本次规划未运行应用测试，不代表功能已实现。
