# Wallet 第一版产品与业务设计

日期：2026-11-02。状态：产品设计及 PWA 实施依据。用户已确认改为 GitHub Pages PWA，原生安卓技术方案停止。

## 1. 范围与技术方向

个人自用、面向安卓手机的生活费记账 PWA。React + TypeScript + Vite，IndexedDB 本地存储，Service Worker 离线缓存，GitHub Pages 发布；四个入口为首页、账单、统计、设置。应用显示人民币，金额按整数分保存，日期按本地日历日计算。首版提供完整备份恢复及 CSV 导出。仓库名 KWallet。

暂不实现云同步、多用户、支付账户对账、自动读取支付账单、借贷分期及实际还款管理。

## 2. 已确认的资金规则

1. 每月 1 日到月末为一个周期。
2. 生活费实际到账后确认入账，常用金额自动填入且允许修改。
3. 正的月末余额加入历史结余，不参与下月日预算。
4. 负的月末余额结转为下月缺口，扣减下月日预算资金。
5. 每日消费扣减当天额度，节省或超出的部分通过剩余资金影响后续日期。

本月预算余额可以为负，表示生活费缺口，不代表某个支付账户的实际负余额。历史结余保持独立，不自动冲抵缺口。显示“预算净余额”而不是宣称这是实际现金或银行资产：预算净余额 = 历史结余 + 本月预算余额。真实债权人、借款与还款需要后续专门建模。

## 3. 页面结构与低保真线框

### 3.1 首页

示例条件：11 月 16 日，日初本月余额 900 元，今日支出 45 元；还有 15 天，历史结余 300 元。

```text
┌────────────────────────────┐
│ 11 月生活费          11月16日 │
│                            │
│ 今日还能花                  │
│ ¥15.00                     │
│ 今日预算 60.00 · 已花 45.00  │
│                    计算说明 ›│
├────────────────────────────┤
│ 本月剩余 ¥855.00   剩余15天  │
│ 明天起日均可花 ¥61.07        │
├────────────────────────────┤
│ 历史结余 ¥300.00       详情 ›│
│ [记支出]          [记收入]   │
├────────────────────────────┤
│ 今日账单               全部 ›│
│ 午餐                 -20.00 │
│ 晚餐                 -25.00 │
├────────────────────────────┤
│ 首页     账单    统计    设置 │
└────────────────────────────┘
```

欠款结转时，本月概况增加“上月结转缺口 ¥200.00”，点开可查看对应月份。待入账时展示“确认生活费到账”卡片。日额度超支时主标题改为“今日已超出”，金额显示超出的正数；总预算为负时另显示“本月资金缺口”。不同状态不能只用颜色表达。

“明天起日均可花”假定今天不再消费；月末最后一天隐藏此项。主卡片旁的计算说明展示日初余额、当日补充、剩余天数和当天支出。

### 3.2 账单

顶部切换月份，显示月收入、净支出；筛选收入/支出/资金调整及分类，支持备注搜索。列表按发生日期倒序分组，每笔显示分类、备注、金额。

点击进入详情，可编辑、删除、记录退款。资金调整单独标记，不混入收入与支出统计。分类停用后旧账单仍可读取。空状态提供“记第一笔”。

删除普通账单支持撤销；删除已有退款的支出须说明关联影响并一并处理，防止孤立退款。编辑历史记录后提示“后续余额和预算已更新”。

### 3.3 统计

月份切换 → 收入/净支出/收支差额 → 收支结构说明 → 分类支出排行 → 每日消费柱状图。

分类使用横向条形图，附金额、占比；柱状图提供日期和金额明细，支持读屏。支出净额 = 支出 − 当月到账退款；收入不含结转和内部划转。若净支出为负，说明退款大于当期支出，不绘制无意义的负比例图，改用金额列表。

“本月收支差额”与“本月预算余额”分开：后者还包含期初欠款和内部划转。统计可点开查看计算明细。

### 3.4 设置及资金详情

设置：常用生活费金额、分类管理、预算规则说明、备份恢复、CSV 导出、主题跟随系统。

资金详情：历史结余、本月预算余额、本月缺口、预算净余额、划转记录。提供“补充本月生活费”和“转回历史结余”。转入额不得超过历史结余；转出不得使本月预算余额变负。这些属于建议交互，尚可调整。

## 4. 核心操作流程

### 首次使用

填写常用生活费金额 → 填写“截至今天开始时剩余的本月生活费”（可为负）→ 单独填写历史结余（非负）→ 进入首页 → 记录今日已发生的消费。

明确提示今日已花金额不要在起始余额和今日账单中重复扣除。用户也可从今天开始记账，不强求补齐过去账单。起始余额不算收入；首次使用月份的报表注明“仅包含起始日期后的记录”。

### 快速记账

点记支出 → 金额输入自动聚焦 → 选择分类 → 保存。日期默认今天，备注选填。收入通过同一表单切换类型。日期限起始日到今天，不把未来计划混为实际收支。

保存时禁用重复提交；成功后才返回并刷新；失败保留输入并提供重试。输入金额必须大于零，至多两位小数，不接受科学计数法和无限大。退款通过原支出详情录入，累计退款不得超过原支出。

### 月初确认生活费

首页待入账卡 → 常用金额与实际到账日 → 确认 → 在一个数据库事务中新增收入并关联月份。确认按钮绑定一次操作标识防止重复提交；已确认后显示“已入账”，但允许用普通收入入口记录补充生活费。金额不同不自动修改常用金额，提供单独选项。

### 跨月

重新打开应用、回到前台或页面跨越午夜时检查日期，按时间顺序重算月份。正结余进入历史结余，负余额只进入下月期初预算。月份记录有唯一键，重算覆盖派生结果，不能反复追加结转交易。连续数月未打开也正确处理。

如果月初没有新收入，预算缺口继续存在，额度为零；实际支出仍能记账，新的缺口继续累计。

### 退款

退款关联原支出，但按照实际退款到账日恢复当期预算、抵减当期支出，不回写过去已实际发生的现金流。原交易显示累计已退款。这是建议的统一统计口径，跨月退款也采用该口径。

### 备份恢复

备份包含账单、分类、初始化、划转、生活费确认关联与设置，带格式版本；CSV 只用于查看，不当作完整恢复源。恢复前校验版本、标识、引用、金额和日期，展示记录数及覆盖说明，创建恢复前备份后事务替换，再重建月度派生数据。失败不覆盖现有账本。

## 5. 计算规则

设某月结束时本月预算余额为 C，历史结余为 H：

```text
下月历史结余 = H + max(C, 0)
下月期初预算 = min(C, 0)
```

不同时创建一笔支出或重复扣债。由月初带入的负数本身占用新收入。当前月预算余额为：

```text
期初预算 + 当月收入 + 当月到账退款
+ 历史结余转入 − 转回历史结余 − 当月支出
```

设 D 为包含今天的剩余天数，O 为今日开始时本月预算余额，A 为当天收入、到账退款、净转入之和，E 为今日支出；均以整数分计算：

```text
今日预算 = floor(max(O + A, 0) / D)
今日还能花 = max(今日预算 − E, 0)
今日超出 = max(E − 今日预算, 0)
本月当前余额 = O + A − E
明天起日均可花 = floor(max(本月当前余额, 0) / (D − 1))，仅 D > 1
```

当日收入或划转会重分配今日及后续预算。零头留在余额中，不额外做舍入支出。预算日期按本地日历计算，不能用毫秒差除以 24 小时。首次使用的起始日期同样参与预算。

历史账单变更后从受影响月份开始重算到当前月；历史日预算展示为按修正后账单推算的值，不宣称是当时屏幕保存的快照。

## 6. 数据逻辑模型

| 实体 | 主要字段 | 约束与用途 |
|---|---|---|
| ledger_initialization | id、start_date、opening_budget_cents、opening_reserve_cents | 单账本一条起始记录；reserve 非负；不计收入 |
| transactions | id、kind、amount_cents、occurred_date、category_id、note、original_expense_id、operation_key、created_at、updated_at | kind=INCOME/EXPENSE/REFUND；金额为正；operation_key 唯一；退款有原支出引用 |
| categories | id、name、kind、icon_key、sort_order、archived | 停用保留历史关联 |
| fund_transfers | id、direction、amount_cents、occurred_date、operation_key、note | RESERVE_TO_BUDGET / BUDGET_TO_RESERVE；金额为正，唯一操作标识 |
| allowance_confirmations | month、transaction_id | month 唯一，transaction_id 唯一；同事务创建或删除关联；普通补充收入不占此标记 |
| month_summaries | month、opening_budget_cents、opening_reserve_cents、closing_budget_cents、closing_reserve_cents、calculation_version | 可重建的派生缓存，month 唯一；当前月 closing 为截至当前的值；不是事实来源 |
| app_settings | id、usual_allowance_cents、theme、schema_version | 常用金额及偏好；不保存可漂移的预算余额 |

发生日期用于业务归属，创建时间用于审计排序。使用稳定 ID；修改、删除、退款校验、划转校验均在事务内完成。为日期、分类及原支出引用建立索引。长整数累加有溢出校验。

核心计算器不依赖页面；通过传入记录和目标日期得到结果。React 页面订阅 IndexedDB 事务完成通知，使用 BroadcastChannel 通知其他标签页重读。

实施简化：首版把收入、支出、退款、划转统一为有类型的 entries，以单个账本文档在 IndexedDB 事务中读改写。月份确认标记附着在生活费收入上；月度汇总由纯函数重算，不存冗余缓存。这样删除生活费收入即可自然释放该月份的确认标记，也不会生成重复结转。数据量上限为十万条；个人账本适用，较大规模需拆分存储及索引。

## 7. 视觉与交互建议

浅色背景、青绿色主色、较少装饰；深色模式跟随系统。系统中文字体，金额使用等宽数字。主要金额约 36–40sp，正文约 16sp，辅助信息约 14sp。4/8dp 间距体系，安卓触控区域至少 48dp。适配系统大字体、读屏、手势导航与键盘遮挡。正常、超支和缺口状态同时用文字与颜色表达。

页面实施为响应式 Web UI：手机底部导航、桌面侧边栏。应用本地字体与本地图标，不依赖远程字体；支持明暗主题。尺寸与可用性通过浏览器检查，安卓真机桌面安装待部署后验证。

## 8. 开发验收场景

1. 11 月结余 300，12 月收入 2000：历史结余 300，本月预算 2000，不是 2300。
2. 11 月缺口 200，12 月收入 2000：本月预算 1800，12 月支出仍为 0。
3. 11 月缺口 500，12 月收入 300 且无支出：12 月缺口 200，继续传至次月。
4. 日初 900、剩余 15 天、支出 45：今日预算 60、今日剩余 15、本月余额 855、后续日均 61.07。
5. 在上例中补充收入 150：今日预算 70、今日剩余 25、本月余额 1005。
6. 历史结余 300 转入 100：历史结余减至 200、本月预算加 100、收入统计不变。
7. 连点生活费确认、反复打开应用、跨月多次检查：不产生重复收入或结转。
8. 补记上月支出、修改月初收入、删除生活费：后续余额正确重算，确认状态同步。
9. 跨月退款：当前预算恢复、当月净支出抵减、无重复收入与历史现金流回写。
10. 月末最后一天、闰年二月、跨年、总预算负数、起始日期在月中：计算有效且不除零。
11. 备份恢复后计算结果相同，损坏备份不改变现有数据。

## 9. 后续开发顺序

本地数据库与独立预算计算器 → 首页及首次使用 → 记账和账单 → 月初确认、结转与划转 → 统计 → 备份恢复 → 浏览器与离线验证 → GitHub Pages 发布 → 安卓真机安装验证。

核心计算优先覆盖上述验收场景，再连接页面。验证结果以 progress.md 的实施记录为准。
